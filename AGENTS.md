## Data access
All data goes through `lib/api-client.ts`. It has two modes, chosen by `process.env.NEXT_PUBLIC_API_MODE`:
- `"mock"` (default when unset, and what you use to develop and demo): serves `docs/fixtures/*.json` via static imports, with 300–800 ms simulated latency, deterministic chat answers from `chat-responses.json`, and `pending → settled` transitions ~10 s after an approval.
- `"live"`: `fetch()` to the relative paths in `ENDPOINTS`, JSON in/out, `ApiError` on non-2xx.

Pages and components never call `fetch` directly and never know which mode is active.

## Stack (already scaffolded on `main`)
Next.js App Router + TypeScript + Tailwind + shadcn/ui, import alias `@/*`. Client components for anything that fetches (`"use client"`). No auth. English UI copy.

## Definition of done
- `NEXT_PUBLIC_API_MODE=mock npm run build` passes on your branch, and `npm run lint` reports no errors in the paths you own (ignore pre-existing warnings elsewhere; do not "fix" backend files).
- Every page has loading, empty and error states.
- The eight scripted requests in `DEMO_SCRIPT` (from `contracts/api.ts`) can be walked through in mock mode with the expected outcomes visible in the UI.
- No secrets, no `localStorage` for anything but the selected mandate id.
- Open the PR as soon as the Traveler page, layout and api-client work (priority items 1–3 of the brief); keep pushing the remaining pages to the same branch. The PR description lists the files you touched and any `TODO(contract)` comments.

The full brief (design, screens, component list, acceptance) is the prompt you were given; `docs/PRD.md` is background reading only — the contract wins over the PRD where they differ.
