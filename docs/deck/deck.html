PerDiem

An AI agent that spends your per-diem — and cannot cross the line.

PerDiem is a policy layer that holds a traveler's per-diem budget and permitted-merchant list for one business trip, stops any agent payment that falls outside it before it reaches the chain, and produces receipts an auditor can verify from records alone.

Kiln API · qwen3-32b on Furiosa NPUs Policy engine in code · 12 checks Ethereum Sepolia · anchored mandate + receipts github.com/keilvher1/perdiem

The problem

The moment after delegation

Payment rails record who paid whom — not who authorized it, or under what conditions.

Good behavior is an accidentAn agent that stays within budget does so only because someone happened to build it that way.
Nothing to reconstructWhen something goes wrong, nobody can tell whether the agent stayed inside the line it was given.
Refusals are silentThere is no record that the agent was stopped, or why — so stopping cannot be trusted either.

PerDiem makes delegated spending answerable: rules are set once, enforced in code before every payment, refusals are recorded, and a third party can verify every payment from the records alone.

How it works

The model proposes. Code decides. The chain settles.

ASKS

Traveler

“Order a bibimbap lunch from Yangjae Kitchen, $12”

→
PROPOSES

Agent on Kiln

qwen3-32b calls one tool:
propose_payment{m1, 12}
It never holds a key.

→
DECIDES

Policy engine

evaluate() — 12 checks in TypeScript, with the real network fee from a gas estimate.

→
SETTLES

Ethereum Sepolia

Transfer to the merchant with calldata PERDIEM|mandateHash|receiptHash

APPROVEBroadcast, ledger entry pending with the tx hash → the client polls → settled. The receipt card links to Etherscan.
STOPLedger entry stopped with every failing reason. No chain call, no second model call — the refusal text is a template.
REPLAYSAuditor: recomputes the mandate hash and compares it with the on-chain anchor, re-runs every decision through the same policy, and matches each receipt hash to the transaction calldata. Status questions (“How much do I have left?”) are answered from the ledger with 0 tokens.
Kiln applies tool_choice: auto only — no tool call ⇒ no proposal ⇒ nothing is spent Only lib/chain.ts touches the wallet, only after APPROVE
PerDiem · Challenge B4 / 9

The boundary

Twelve checks, in code, before anything reaches the chain

lib/policy.ts · evaluate() is a pure function called in lib/agent.ts before any call into lib/chain.ts. Every failing check is reported, not just the first.

MANDATE_NOT_ACTIVE

Principal paused or revoked the mandate — the kill switch.

BEFORE_START

The trip window has not opened yet.

EXPIRED

The deadline has already passed.

UNKNOWN_MERCHANT

Not in the catalog snapshot hashed with the mandate.

MERCHANT_NOT_ALLOWED

In the catalog, but not on the permitted list.

CATEGORY_NOT_ALLOWED

The merchant's category is not permitted.

BLOCKED_KEYWORD

Memo or the traveler's words mention a blocked item.

INVALID_AMOUNT

Zero, negative, or not a number.

OVER_PER_TX_CAP

Above the single-payment cap.

FEE_UNAVAILABLE

Fee could not be estimated → refuse rather than guess.

OVER_BUDGET_WITH_FEES

Amount + real network fee exceeds what is left. Never rounded.

DUPLICATE

Same merchant and amount within five minutes.

The model never holds keys 17 unit-test blocks · npm test Mandate hash covers terms + catalog, not status Stopping is recorded, not silent

PerDiem · Challenge B6 / 9

Verifiable by a stranger

The audit does not trust our database

  • 1Mandate hash recomputed from the exported terms equals the hash anchored on-chain when the budget was granted.
  • 2Every decision replayed through the same evaluate(), rebuilding spend-so-far from earlier entries.
  • 3Receipt hash recomputed from the entry equals the stored one and the one in the payment's calldata.
  • 4Recipient and amount on-chain match the catalog wallet and the ledger amount.
$ npm run verify -- evidence/mandate-<id>.json \ evidence/ledger-<id>.json … ✅ anchor memo matches recomputed hash … ✅ stored APPROVE == recomputed APPROVE … ✅ calldata memo == recomputed hashes (excerpt of evidence/12-verify.txt after the evidence run)

Records + a public Sepolia RPC only — no database, no API. Edit one stored decision by hand and it turns red.
